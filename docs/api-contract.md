# Current API contract and generated client

`contracts/pocketquests-v1.openapi.json` is generated from the actual API Program, endpoint metadata and public DTOs by `ApiContractTests`. It is the only maintained operation/schema authority. The TypeScript emitter consumes that document; the separate `tools/PocketQuests.WireFixtures` tool only serializes a completed domain occurrence and the catalog for compatibility checks. It defines no routes or schemas.

Run `scripts/Test-ApiContract.ps1` after configuring the existing Identity package feed or source references. It runs actual-Program contract/HTTP tests, compares endpoint OpenAPI, regenerates and compares the .NET wire fixtures, and verifies the generated TypeScript. Use `-NoBuild -Configuration Release` after building the API test assembly. To update intentionally, run `scripts/Test-ApiContract.ps1 -Update` and review all resulting contract, fixture and client changes. Backend CI runs this complete check. `scripts/Test-ClientContract.ps1` verifies fixture/client drift without opening SQL or calling Identity; its Services reference supplies the real Contracts mappings and requires the same Data and Identity build dependencies as the API. The independent Generated API client workflow checks TypeScript drift directly with Node; it does not substitute for endpoint or fixture verification.

Response DTO numbers are numbers and serialized properties are required, including nullable properties. Request inputs retain optional defaults and numeric-string binding. `QuestInput`/`ShareInput` therefore differ from response `Quest`/`Share`. The emitter handles this document's references, unions, nullability, arrays, dictionaries and required query parameters. It fails on unsupported mappings instead of silently widening them. TypeScript does not enforce numeric-string patterns at runtime; API HTTP tests and wire-schema regression checks cover those constraints.

The mobile session uses `src/api/client.ts` and generated request/response types. Local pending flags and clock samples remain extensions in `src/shared/contracts.ts`. The local queue records numeric clock evidence and full preview terms, a narrower valid subset of accepted command inputs. Refresh retries serialize the command once, preserving operation IDs and timing proofs. Binary exports keep their dedicated download path and are excluded from the JSON client.

This describes the current `/api` routes. It adds no versioned runtime route and changes no persisted receipt format, Identity behavior or quest rules. The fixture tool uses the real aggregate and the Services mappings/catalog service to serialize public Contracts; successful client checks alone do not establish SQL/EF behavior. Run `scripts/Test-RelationalSchema.ps1` for the complete disposable SQL/API/domain lane and add `-IdentityIntegration` for the source-Identity integration assembly.
