# Backend services and persistence

The API has one relational execution path for commands, initialization, reads, synchronization, export, maintenance and private account lifecycle. Application and persistence-aware Domain services have been removed. Domain contains the existing pure rules and aggregates; reward formulas and public JSON contracts are unchanged.

| Layer | Responsibility |
| --- | --- |
| API | Named typed handlers, authentication, HTTP status/rate/error policy, worker and private-message adapters. |
| Contracts | Public models, requests, responses and service-facing types. No persistence entities. |
| Services | Operation orchestration, validators, retained-source selection and explicit mappings between Contracts, pure Domain and Data entities. |
| Domain | Catalog, calendar, recurrence, completion/Undo and progression rules; no Data, EF or Identity dependency. |
| Data / Database | Scoped EF CRUD, purpose-specific queries and transaction execution; explicit entities/configurations; DACPAC-owned tables, constraints, indexes and descriptions. |

`QuestService` verifies trusted ownership/lifecycle before receipt lookup, loads current or requested historical sources, and invokes pure Domain rules. Focused `ProfileHistoryService`, `QuestDefinitionService`, `QuestSeriesService`, `QuestOccurrenceService`, `ProgressService` and `QuestCommandHistoryService` protect history and call their typed Data services directly. Existing entities use ordinary EF tracking; each feature batches its own inserts/removals. There is no universal change bag or Data Apply dispatcher. `QuestTermHistory` is a read-only historical identity lookup. Mapping classes perform pure field conversions; services own audit clocks, random IDs, historical decisions and transaction orchestration. Initialization, anchors, export, reconciliation and lifecycle have named services. Test adapters call those real services and contain no alternate workflow implementation. The [engineering standards](engineering-standards.md) define these rules for future changes.

Data queries filter ownership, current heads, selected terms, retained replay version and bounded occurrence/candidate pages before materialization. Missing current revisions remain visible through left joins so validation fails closed. Current state reads do not load full receipts or reward projections and never save account state. Export uses a RepeatableRead snapshot. Full-state and historical replay responses still require chronological account facts; there is no claim of constant memory and no arbitrary history cutoff. Tests measure both SQL command count and actual materialized entity types.

The transaction executor rejects nested transactions and unrelated staged changes before taking ownership. Before commit starts it retries transient SQL failures at most twice, disposing the old transaction and clearing owned tracking so the complete operation reacquires its account lock and reloads state. Cancellation and permanent errors escape. Once commit starts it never automatically repeats an uncertain operation; a subsequent caller retry resolves the retained receipt. Rowversion and SQL uniqueness/composite ownership constraints remain additional concurrency boundaries.

Immutable typed command, definition, series, occurrence, completion and Undo facts reconstruct exact old responses. Receipts store only the original projection instant and a null feedback placeholder, not full account snapshots. Shared validation rejects unsupported retained ruleset/display versions and inconsistent frozen XP on both current and historical paths. Anchored late arrival keeps the original term/proof rules, fractional elapsed time, ordinary offline restart and bounded continuation with no blanket age cutoff. Deferred commands consume neither receipt nor proof ordinal.

Lifecycle uses explicit authoritative Identity inputs because authentication runs before a public current-account principal exists. The same Data transaction stages pause/barrier/anchor invalidation and the owned acknowledgment. Recovery remains paused until explicit product resume. Erasure removes only the account's linked shared records and retains `ErasureMarker` as Id plus the original verified CreatedAt for 35 days; retries/restores never refresh that instant. Shared Audit/Outbox schema and ownership remain upstream responsibilities.

`Test-RelationalSchema.ps1` creates a unique disposable LocalDB instance and deploys the actual DACPAC for parity, metadata, negative writes, ownership, concurrency, replay, erasure/restore, runtime permissions and real API tests. `Test-ApiContract.ps1` checks endpoint-generated OpenAPI, HTTP compatibility, actual Contracts serialization fixtures and generated mobile client equality. Source-Identity integration uses `-IdentityIntegration` after a source-mode build. Its Tests/BrowserHost projects require Identity source mode and use the ignored source lockfiles; package-mode validation uses SchemaTests and its committed package lock. Mobile lint/typecheck/logic tests are a separate required lane. Native device/provider/signing, live broker and deployment acceptance are separate release gates.
